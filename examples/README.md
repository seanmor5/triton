# Examples

A guided tour of Triton-Elixir, from "hello world" to things only the BEAM can do. Each script is self-contained, verifies its own results, and runs with `source scripts/env.sh && mix run examples/<file>.exs` (all require a CUDA GPU). Start with [`01_vector_add.exs`](01_vector_add.exs), which walks one kernel through the whole stack: `defkernel` tracing, the generated TTIR, the pure-Elixir reference interpreter, the native MLIR → PTX → CUBIN pipeline, and a bandwidth benchmark. [`02_softmax.exs`](02_softmax.exs) fuses a full softmax row into one kernel with axis reductions and cross-checks interpreter, GPU, and a plain-Elixir reference. [`03_matmul_autotuned.exs`](03_matmul_autotuned.exs) shows the symbolic `for ... range ... reduce` loop compiling to a real `scf.for`, then lets `Triton.Autotuner` compile ~26 tensor-core matmul configs concurrently on the BEAM and race them on the GPU, printing a timing leaderboard and TFLOPS. [`04_flash_attention.exs`](04_flash_attention.exs) implements single-head flash attention with an online softmax, carrying `{acc, m_i, l_i}` through one multi-carry loop, verified against a plain-Elixir attention. Finally, [`05_hot_kernel_server.exs`](05_hot_kernel_server.exs) is the OTP showcase: a GenServer owns a compiled kernel and serves GPU requests while the autotuner finds a faster config in a background Task, which is then hot-swapped in mid-traffic — atomically, with zero dropped requests.
